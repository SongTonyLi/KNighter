Refinment Plan:
1. Root cause of the false positive:
   - The checker currently treats any later load from a region written by `avio_read()` as suspicious unless the region was “cleared” by a branch condition that directly mentions the call or a variable initialized from it.
   - This is too syntactic and too coarse:
     - It does not understand that the return value of `avio_read()` may be stored into a variable and checked later through ordinary path constraints.
     - It does not model sanitizing follow-up logic after a short read, such as:
       - zero-filling the unread tail with `memset()`
       - shrinking the valid extent with `av_shrink_packet()`
     - It tracks only the base destination region, not whether the destination has become safe again after repair logic.
   - In the ASF case, the code checks `read != requested`, then either:
     - fills the unread tail with `memset()` and promotes `read` to the requested size, or
     - shrinks the packet so future reads are constrained to the initialized prefix.
     The current checker misses this repair pattern and reports on a later load.

2. Specific fixes:
   - Introduce richer program state:
     - track destination region written by `avio_read()`
     - track the return-value variable associated with that `avio_read()`
     - track the requested-size expression
     - track a “pending short-read check” relation from return variable to destination region
   - Clear the warning state not only on direct branch conditions, but also when the branch condition references the stored return variable.
   - Recognize post-read repair/sanitization patterns in `checkPreCall`:
     - `memset(dst + read, 0, requested - read)` on the same tracked destination
     - `av_shrink_packet(&pkt, frag_offset + read)` or more generally `av_shrink_packet` involving the same object whose backing data region was read into
   - Suppress reports when the current path already established a full-read/equivalent-safe state via those recognized repairs.
   - Keep true positives by still reporting:
     - direct use after unchecked `avio_read`
     - `memcmp()` and ordinary loads from the destination buffer when no branch check or repair logic occurred

3. Edge cases / regressions:
   - Multiple outstanding `avio_read()` calls in the same function:
     - state is keyed by destination region and return variable
   - Calls where result is ignored:
     - still tracked and still reported
   - Direct condition with the call expression:
     - still handled
   - Full-read helper `ffio_read_size()`:
     - explicitly excluded as before
   - Sibling-field false positives:
     - preserved with overlap/subregion filtering
   - Sanitization recognition is conservative:
     - only clears when we can match the repaired destination region to the tracked destination region

4. Clang-18 compatibility:
   - Uses only standard checker callbacks and `REGISTER_MAP_WITH_PROGRAMSTATE`
   - Avoids newer unstable APIs
   - Keeps all original includes, as requested
